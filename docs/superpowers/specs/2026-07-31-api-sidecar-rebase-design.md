## Audit findings

The sidecar was audited before this rebase. The following were verified as
correct and need no change: peer-ID path traversal is blocked by a regex
allowlist combined with `O_NOFOLLOW` (defeating symlink swaps); `exec.Command`
uses argv with no shell and a hardcoded service list; token comparison is
constant-time; the server sets `SetTrustedProxies(nil)` and `ReadHeaderTimeout`
and shuts down gracefully; the stats hub builds snapshots outside the lock with
per-client send goroutines.

Five issues require fixes.

### Finding 1 — AWG params leak the header protection key (High)

`api/config.go:readAWGParams()` reads every `AWG_*` line from
`/config/server/awg_params` into a generic map served by `GET /api/v1/server`:

```go
key := strings.TrimPrefix(strings.TrimSpace(k), "AWG_")
key = strings.ToLower(key)
params[key] = strings.TrimSpace(v)
```

Before AWG 3.0 that file held only obfuscation parameters, which clients receive
anyway. As of `fc3ecdc` it also holds `AWG_HEADER_PROTECTION_KEY` — a symmetric
secret generated by `awg genpsk` that must be identical on the server and every
client. Neither branch is wrong alone; the leak is created by the merge.

**Fix:** replace pass-through with an explicit allowlist. Only these keys are
emitted: `version`, `jc`, `jmin`, `jmax`, `s1`–`s4`, `h1`–`h4`, `i1`–`i5`,
`content_padding`, `rekey_after_time`, `rekey_timeout`, `reject_after_time`,
`keepalive_timeout`, `max_handshake_attempts`. Anything unrecognised is dropped.

This fails closed: a future secret added upstream is excluded automatically
rather than leaking until someone notices. The cost is that genuinely new
non-secret parameters need a one-line addition to be visible — an acceptable
trade for a monitoring endpoint.

### Finding 2 — WebSocket token leaks into access logs (Medium)

Both WS routes authenticate via `?token=`. `api/go.mod` pins gin v1.10.0, whose
`logger.go:273` appends the raw query to the logged path:

```go
if raw != "" {
    path = path + "?" + raw
}
param.Path = path
```

Every WS connect therefore writes `/api/v1/ws/stats?token=<secret>` to the
sidecar's stdout. It does not reach `/api/v1/logs` — that store carries only
`awg` and `api` sources, not gin's access log — so the blast radius is
`docker logs` plus any reverse-proxy access log in front of the sidecar.

**Fix**, in precedence order — the handler accepts the first that is present:

1. `Sec-WebSocket-Protocol: bearer, <token>` — the primary mechanism, and the
   only header browsers can set on a WebSocket handshake. The server echoes back
   the `bearer` subprotocol on success.
2. `Authorization: Bearer <token>` — for non-browser clients (curl, the bot).
3. `?token=` — retained for one release, emitting a deprecation warning.

Additionally, `/api/v1/ws/stats` and `/api/v1/ws/logs` are added to the gin
logger's `SkipPaths` so the legacy form stops being written to the access log
while it remains supported.

### Finding 3 — Swagger UI is unauthenticated and on by default (Low–Medium)

`r.GET("/swagger/*any", ...)` is mounted outside the `v1` auth group and
`swaggerEnabled()` returns true when `API_SWAGGER` is unset. The full API
surface is readable by unauthenticated callers. The existing code comment
acknowledges this as a backward-compatibility choice.

**Fix:** invert the default so Swagger is opt-in via `API_SWAGGER=true`, and
document the change as breaking in the PR description and CHANGELOG. The
endpoint exposes no secrets, only the API shape, which is why this is not rated
higher.

### Finding 4 — `build_version` never reaches the sidecar in client mode (Low)

`init-amneziawg-confs/run` ends with:

```bash
cp /build_version /config/server/build_version 2>/dev/null || true
```

`/config/server` is created only in server mode, by the `mkdir -p` that
`generate_awg_params` gained in the AWG 3.0 merge (`fc3ecdc`). In client mode
`generate_awg_params` never runs, so the copy silently fails and a sidecar
attached to a client-mode container reports no version.

**Fix:** `mkdir -p /config/server` immediately before the copy, so the path
holds in both modes.

### Finding 5 — Token handling in the entrypoint (Low)

`api/entrypoint.sh` prints the generated token to stdout, and creates
`api_token` before `chmod 600`, leaving a brief window at the default umask.

**Fix:** create the file with a restrictive umask, then write. Keep the one-time
stdout print — an operator needs some way to retrieve the generated token — but
note in the docs that it is recoverable from `/config/server/api_token`.

## Image and toolchain alignment

| Component | PR #10 | This branch |
|---|---|---|
| `api-builder` base | `golang:1.24.4-alpine` | `golang:1.25.12-alpine` |
| `awg-api` base | `alpine:3.21` | `alpine:3.24` |
| `runtime` base | `baseimage-alpine:3.21` | `baseimage-alpine:3.24` (from master) |
| `api/go.mod` directive | `go 1.24.4` | unchanged |

The `go.mod` directive stays at 1.24.4 deliberately: Go 1.25 builds it without
issue, and raising the floor is churn with no benefit.

CI keeps master's Dockerfile-as-source-of-truth version resolution and its
release job, with the two-target build layered on top. The release job remains
driven by the `AMNEZIAWG_TOOLS_VERSION` pin and is unaffected by the API image.

### Known verification gap

The full compose-stack test — two containers sharing a netns via
`network_mode: service:amneziawg` — cannot be validated on this macOS host,
because Docker Desktop's VM does not reproduce Linux netns sharing semantics
faithfully enough to be meaningful. PR #10 left this box unchecked and this
branch will too. It must be run on a Linux host before merge, and the plan will
say so rather than silently marking it done. The same applies to the multi-arch
(amd64 + arm64) build, which is exercised by CI on merge rather than locally.
