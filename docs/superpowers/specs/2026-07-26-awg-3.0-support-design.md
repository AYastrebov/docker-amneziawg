# AWG 3.0 Protocol Support — Design

Date: 2026-07-26
Status: Approved by user. **Implementation paused** pending an official
amneziawg-tools release that includes PR #60 ("feat: AmneziaWG 3.0").

## Goal

Support AmneziaWG 3.0 protocol parameters in the docker-amneziawg image while
keeping AWG 2.0 (default) and 1.5 behavior unchanged.

## Background

- The image already builds `amneziawg-go v3.0.1`, which implements the 3.0
  feature set (header protection, content padding, randomized timers).
- **Datapath requirement:** the 3.0 feature set lives entirely in
  `amneziawg-go` (userspace). `init-amneziawg-module/run` uses the kernel
  datapath whenever `ip link add … type wireguard` succeeds and only falls
  back to userspace otherwise — so on any host with a wireguard-capable
  kernel module (mainline Linux ≥ 5.6, unless it is a 3.0-capable
  amneziawg.ko, which this image does not build or load) the 3.0 keys are
  handed to a module that cannot apply them: the tunnel either fails to
  come up or silently ignores the 3.0 params. `AWG_VERSION=3.0` therefore
  requires userspace mode. There is no override to force userspace; the
  module init auto-detects. This constraint must be documented and the 3.0
  tunnel test must confirm `**** … using userspace amneziawg-go ****` is in
  the log before trusting the result.
- The released `amneziawg-tools v1.0.20260618-2` cannot parse the new 3.0
  config keys — `awg setconf` fails with "Line unrecognized", so tunnels would
  not come up. The upstream branch `feat/awg3` (PR #60) adds full native
  parsing (config keys, uapi passthrough, base64→hex key conversion). We do
  NOT build from that branch; we wait for the official release that merges it.

### New 3.0 config keys (all `[Interface]`-level unless noted)

| Config key | Format | Semantics |
|---|---|---|
| `HeaderProtectionKey` | base64 32-byte key (like PresharedKey) | Shared symmetric key; ChaCha20-obfuscates packet headers using a nonce taken from S-padding. **Must be identical on server and all clients.** Requires S1–S4 ≥ 12 (enforced by amneziawg-go). |
| `ContentPaddingAddition` | `lo-hi` or single value | Random extra zero-padding per transport packet. Client-side (each side pads its own). `0` = off. |
| `RekeyAfterTime` | `lo-hi` seconds | Default 120s. |
| `RekeyTimeout` | `lo-hi` seconds | Default 5s. |
| `RejectAfterTime` | `lo-hi` seconds | Default 180s. |
| `KeepaliveTimeout` | `lo-hi` seconds | Default 10s. |
| `MaxHandshakeAttempts` | `lo-hi` count | Default 18. |
| `PersistentKeepalive` (`[Peer]`) | now accepts ranges | Client-side; not auto-generated by this project. |

Timer params are device-level and client-side: each side uses its own values,
they do not need to match. When a 3.0 param is absent, amneziawg-go falls back
to exact 2.0 behavior — so 2.0 configs are unaffected by the go binary.

Validation invariants (from amneziawg-go `device/timers.go`, mirrored by
AmneziaWG-Architect):
- `RejectAfterTime.lo > KeepaliveTimeout.lo + RekeyTimeout.lo`
- `RekeyAfterTime.hi < RejectAfterTime.lo`
- `MaxHandshakeAttempts.lo >= 1`

## Design

### 1. Build (Dockerfile)

- **Prerequisite:** an official amneziawg-tools release that includes PR #60
  (AWG 3.0 config parsing). Implementation starts only after it is published.
- The only build change is bumping `ARG AMNEZIAWG_TOOLS_VERSION` to that
  release tag. The clone line stays `git clone --branch ... --depth 1`.
- amneziawg-go stays `v3.0.1`. The existing daily upstream-check workflow
  detects the new tools release on its own — no CI changes needed.

### 2. Config generator (`root/etc/s6-overlay/s6-rc.d/init-amneziawg-confs/run`)

- `AWG_VERSION` accepts `3.0`; default remains `2.0`; `1.5` untouched.
- New optional env vars:
  `AWG_HEADER_PROTECTION_KEY`, `AWG_CONTENT_PADDING`,
  `AWG_REKEY_AFTER_TIME`, `AWG_REKEY_TIMEOUT`, `AWG_REJECT_AFTER_TIME`,
  `AWG_KEEPALIVE_TIMEOUT`, `AWG_MAX_HANDSHAKE_ATTEMPTS`.
- In 3.0 mode, randomized defaults (aligned with AmneziaWG-Architect "medium"
  intensity):
  - `HeaderProtectionKey`: `awg genpsk` if unset (full-entropy 32-byte
    symmetric key, like PresharedKey — `awg genkey` would emit a bit-clamped
    Curve25519 private key, which is the wrong generator for a symmetric
    ChaCha20 key); one shared key reused for server + all peer confs.
  - `ContentPaddingAddition`: `lo = shuf 16-72`, `hi = shuf (lo+8)-128`.
  - `RekeyTimeout`: `lo = 4-6`, `hi = lo + 1-4`.
  - `KeepaliveTimeout`: `lo = 8-14`, `hi = lo + 2-8`.
  - `RekeyAfterTime`: `lo = 100-120`, `hi = lo + 10-25`.
  - `RejectAfterTime`: `floor = RekeyAfterTime.hi + KeepaliveTimeout.hi +
    RekeyTimeout.hi + 15`; `lo = max(170, floor)`; `hi = lo + 10-25`.
  - `MaxHandshakeAttempts`: `lo = 12-18`, `hi = lo + 2-10`.
  - S-value floors raised to ≥ 12 in 3.0 mode (S3: 12-55, S4: 12-27; S1/S2
    already ≥ 15). S4 stays ≤ 32 per protocol cap.
  - Range env vars are validated: warn when the timer invariants above are
    violated by user-supplied values, including `MaxHandshakeAttempts.lo >= 1`.
- New params are persisted in `/config/server/awg_params`, loaded by
  `load_awg_params`, saved by `save_vars` (`ORIG_*`), and included in the
  change-detection comparison — same lifecycle as existing AWG params.
- 2.0/1.5 generation paths are not modified.

### 3. Templates

- `root/defaults/server.conf` and `root/defaults/peer.conf` stay unchanged so
  existing user templates in `/config/templates` keep working.
- The 3.0 keys are appended programmatically to the `[Interface]` section of
  server and peer confs when `AWG_VERSION=3.0`, via a helper modeled on
  `append_awg_signatures` / `append_awg_signatures_to_interface`. The same
  values (key, padding, timers) are written to the server conf and every peer
  conf.

### 4. Client mode

- No changes. User-mounted confs with 3.0 keys parse natively via the patched
  tools.

### 5. Docs

- README: env var table entries for the new vars, `AWG_VERSION=3.0`
  description, note that both ends must run 3.0-capable software when
  `HeaderProtectionKey` is used, and a note that `AWG_VERSION=3.0` requires
  userspace mode (`amneziawg-go`) — it does not work on hosts using the
  kernel wireguard datapath (see Background).
- CHANGELOG entry.

### 6. Testing

- `shellcheck` on the modified script.
- Build the image locally.
- Run with `AWG_VERSION=3.0 PEERS=2`: verify generated server/peer confs
  contain the 3.0 keys, timer invariants hold, S-values ≥ 12, and the tunnel
  comes up (`awg show` shows the interface). **First confirm the log shows
  `using userspace amneziawg-go`** — if the test host uses the kernel
  datapath (see Background), the 3.0 params are not applied and this test is
  meaningless. Block/unload the host wireguard module, or run on a host
  without one, to force userspace.
- Regression runs with `AWG_VERSION=2.0` and `1.5`: confs unchanged in shape,
  tunnel comes up.
- Restart with unchanged env: "No changes to parameters" path (persistence).

## Out of scope

- Ranged `PersistentKeepalive` generation (supported by the tools branch for
  hand-written confs, but the generator keeps writing `25`).
- `<d>`/`<ds>`/`<dz>` obfuscation tags (parsed by amneziawg-go but not wired
  into its send path; not emitted by AmneziaWG-Architect either).
- `AdvancedSecurity` peer key (kernel-module only; rejected in userspace mode).
